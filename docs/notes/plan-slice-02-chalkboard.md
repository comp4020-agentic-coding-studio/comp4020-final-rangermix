# Slice 02, "What the night left behind": Implementation Plan

> Method fixed by [ADR 0014](../adr/0014-build-the-rest-in-vertical-slices-each-with-a-spec.md):
> built natively in one session, test first (each test seen failing before
> its code), committed and pushed per task (a push to `main` deploys
> through CI), then a fresh review whose brief and findings are files, then
> deployed and checked live.

**Goal:** the server writes a chalkboard line when a cat does something
worth telling. The board keeps a rolling 24 hours and shows the latest 8:
on desktop in the panel left of the room, on the phone by tapping the
chalkboard. The night's traces (toppled pieces, and toys a cat scattered)
stay until someone tidies them, through restarts and replays.

**Architecture:** a chalkboard line is a wire type (`ChalkLine`, in
`server/src/protocol.rs`) built from fixed fields: when, which cat, and
what it did, as a tagged enum whose only strings are a cat's name, a
person's username and a furniture kind. No field can hold text anyone
typed. The world keeps the lines of the last 24 hours in memory
(`server/src/world/chalk.rs`), writes each new one to a `chalkboard` table
(migration 3), broadcasts it (`ServerMsg::Chalked`), and sends the latest 8
in the snapshot. The replay of slice 01 writes lines like any other step,
and its end-of-replay save rewrites the table. The client renders a line's
words itself (`client/src/chalk.ts`), in the left panel and in a board
dialog opened from the chalkboard tile.

**Tech stack:** Rust (the world, rusqlite, ts-rs), TypeScript (the client,
vitest with jsdom), Playwright browser checks in `spec/browser.test.ts`,
vitest spec checks.

**Spec:** [`docs/slices/02-what-the-night-left-behind.md`](../slices/02-what-the-night-left-behind.md),
approved 2026-10-14 with its proposed default (the board names people by
username, only for what a cat did with them). Design:
[`docs/design.md`](../design.md) "The room" (traces, the chalkboard), "The
client" (the readable chalkboard), "Persistence and fast-forward",
"Checks"; [ADR 0002](../adr/0002-make-a-cat-cafe-where-company-forms-around-the-cats.md).
Written 2026-10-14 from the code at `b63ea6b`, with slice 01 built and in
review.

## Global constraints

- Chalkboard: rolling 24 hours, latest 8 lines shown. Both numbers go into
  `content/tuning.toml` (`chalk_hours = 24`, `chalk_shown = 8`) and
  design.md's "Numbers to tune".
- AGENTS.md: never store or log what anyone says (the board stores cats'
  doings only); the server decides every outcome; every action works by
  keyboard, touch and mouse at 390×844 and 1920×1080 and survives a
  resize; generated TypeScript is never edited by hand (`client/src/protocol/`
  is regenerated by `cargo test`, and `scripts/check-protocol.sh` passes);
  cats change through `content/`, not code.
- Slice 01's replay rules hold: a replay writes nothing until it ends,
  logs nothing, and saves what it changed before the doors open.
- `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`,
  `cargo test`, `pnpm typecheck`, `pnpm -C client check` and the spec pass
  before each push.

## Review focus

The five conditions the spec implies but no "done when" line tests, most
likely first. Each has its test in the task that owns the code.

1. **A busy afternoon crowds out the night.** Forty first meetings in an
   hour would fill the board with "met" lines. The board shows the latest 8
   whatever their kind; a cat's same doing (a game with the toys, a perch, a
   greeting for the same person, a look at the same kind of piece) is
   written at most once an hour. (Task 1.)
2. **A username that looks like markup** (`<b>`, `&amp;`) is shown as text,
   never parsed, in the panel, the dialog and the announcer. (Task 4.)
3. **A line that is exactly 24 hours old** drops off; one a millisecond
   younger stays, in the snapshot and on the client, which filters by the
   server's clock rather than its own. (Tasks 1 and 4.)
4. **A store row that can't be read** (a hand edit, a future kind) is
   skipped with a warning, and the café still wakes. (Task 2.)
5. **The board dialog and a menu at once**: opening the board closes any
   open menu, and Escape closes the board and gives the focus back to the
   room. (Task 4.)

## Decisions made in this plan

1. **What becomes a line**, from the `cat` log events phase 3 has, plus
   the first meeting:

   | Doing | Line | When written | At most |
   | --- | --- | --- | --- |
   | `knockedOver { piece }` | "Burakku knocked over the plant"; toys: "Tora scattered the toys" | the piece goes over | every time |
   | `met { with }` | "Mochi met sam for the first time" | the first sniff of a stranger's hand | every time (once per cat and person, ever) |
   | `lap { with, minutes }` | "Mochi slept on sam's lap for 20 minutes" | a lap of 5 minutes or more ends | every time |
   | `greeted { with }` | "Mochi greeted sam at the door" | the greeting | once an hour per cat and person |
   | `playedWith { with }` | "Tora played with sam" | a welcomed game | once an hour per cat and person |
   | `played {}` | "Tora played with the toys" | a game with the toys | once an hour per cat |
   | `investigated { piece }` | "Tora looked over the new lamp" | a look at a new piece | once an hour per cat and kind |
   | `perched {}` | "Tora watched the street from the window seat" | a perch | once an hour per cat |

   The first meeting isn't a `cat` log line (it's the `pet` action's
   `sniff` outcome), but it is a cat's doing with someone, it's what
   regulars-to-be leave behind, and it's the one line a visitor can cause
   for certain, which the spec's "within a second" check needs.
2. **Scattered toys are the toys knocked over.** The toys already topple
   like the plant and the lamp (phase 3). A toppled toys piece is drawn
   strewn about its tile, reads "scattered" in words, and "Gather up the
   toys" tidies it (the same `tidy` message). A cat playing with the toys
   while nobody is inside may also scatter them, with a chance of half its
   playfulness (Tora 0.475, Burakku 0.2, Mochi 0.15), so Tora leaves traces
   too. Scattered toys can't be played with until someone gathers them up.
   That is phase 3's rule that cats play only with toys that are still
   there.
3. **Lines are kept in memory for 24 hours** (at most 500, the oldest
   dropping first) and written to the store as they happen. Each tick drops
   lines 24 hours old and deletes their rows. A replay's lines and drops
   reach the store in its end-of-replay save, which rewrites the table.
4. **A line is stored as its JSON**, one row per line with its time, in
   migration 3. Rows that won't read are skipped with a warning.
5. **The client words the lines** (`client/src/chalk.ts`), in Canberra time
   ("3:12am"), oldest first, and keeps the latest 8 within 24 hours by the
   server's clock. A new line is announced politely ("On the chalkboard:
   …").
6. **Where the board is read.** Desktop: a "The chalkboard" section at the
   top of the left panel (the panel becomes two sections, the board and
   your cats). Phone (700 px wide or less): that section is hidden, and the
   chalkboard tile in the room (the `C` on the street wall) opens a board
   dialog, by tap, click, or Tab and Enter, at every size. The dialog is a
   `role="dialog"` with a heading, the list and a Close button; it takes the
   focus, Escape or Close shut it, and the focus goes back to the room.
7. **The chalkboard is a target.** It joins the Tab cycle as "the
   chalkboard", and a tap, click or Enter on its tile opens the board
   rather than a menu.

## Not in this plan

- People never write on the board, and no line carries anything said.
- Art for the board, the strewn toys and the dialog beyond what's drawn
  here is slice 05's.

```rust
//! The chalkboard (design.md, "The room"): what the cats got up to over a
//! rolling day, written by the server from what they do. People never write
//! on it, and nothing anyone said can reach it: a line is fixed fields.
use super::{Out, To, World};
use crate::protocol::{ChalkLine, ChalkWhat, ServerMsg};

/// At most this many lines are kept, the oldest dropping first.
const KEPT: usize = 500;
/// The same doing by the same cat is written at most this often.
const AGAIN_MS: u64 = 3_600_000;

/// Doings told every time; the rest at most once an hour per cat and key.
fn every_time(what: &ChalkWhat) -> bool {
    matches!(what, ChalkWhat::KnockedOver { .. } | ChalkWhat::Met { .. } | ChalkWhat::Lap { .. })
}

/// What makes two lines the same doing: its kind and whom or what it was with.
fn key(what: &ChalkWhat) -> (std::mem::Discriminant<ChalkWhat>, Option<&str>) {
    let with = match what {
        ChalkWhat::Greeted { with } | ChalkWhat::PlayedWith { with } => Some(with.as_str()),
        ChalkWhat::Investigated { piece } => Some(piece.as_str()),
        _ => None,
    };
    (std::mem::discriminant(what), with)
}

impl World {
    pub(super) fn chalk(&mut self, now: u64, i: usize, what: ChalkWhat, out: &mut Vec<Out>) {
        let cat = self.cats[i].def.name.clone();
        let again = self.chalk.iter().rev().take_while(|l| now.saturating_sub(l.at) < AGAIN_MS)
            .any(|l| l.cat == cat && key(&l.what) == key(&what));
        if again && !every_time(&what) {
            return;
        }
        let line = ChalkLine { at: now, cat, what };
        if let Some(store) = &self.store {
            let json = serde_json::to_string(&line).expect("a chalkboard line serialises");
            store.fire(move |c| crate::store::put_chalk(c, now, &json));
        }
        out.push(Out { to: To::All, msg: ServerMsg::Chalked { line: line.clone() } });
        self.chalk.push_back(line);
        while self.chalk.len() > KEPT {
            self.chalk.pop_front();
        }
    }

    /// Drops lines a day old, from memory and the store.
    pub(super) fn chalk_tick(&mut self, now: u64) {
        let day = self.tuning.chalk_hours * 3_600_000;
        let before = self.chalk.len();
        while self.chalk.front().is_some_and(|l| now.saturating_sub(l.at) >= day) {
            self.chalk.pop_front();
        }
        if self.chalk.len() < before && let Some(store) = &self.store {
            let cutoff = now.saturating_sub(day);
            store.fire(move |c| crate::store::drop_chalk(c, cutoff));
        }
    }

    /// The latest lines, oldest first, for a snapshot.
    pub fn chalk_view(&self) -> Vec<ChalkLine> {
        let skip = self.chalk.len().saturating_sub(self.tuning.chalk_shown);
        self.chalk.iter().skip(skip).cloned().collect()
    }
}
```
